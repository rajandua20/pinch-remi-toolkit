Issues encountered

Time-Travel doesn't trigger processing via raw API. Header verified accepted, but scheduled DD payments never flipped to dishonoured across create/read/poll patterns. Docs hint the Dev Portal "sends headers back and forth". Mitigation: synchronous card-path dishonours via payment link + real overnight run; question queued for #hackathon-help.
Hosted pay page unreachable from build container (network allowlist covers api/auth hosts only) — automated link-payment seeding moved to manual/local browser.
API strictness the docs don't state: bank account numbers 3–9 digits; allowedPaymentMethods required on payment links; card sources need a CaptureJS token (no raw PAN server-side).
Timezone trap: transactionDate comes back as midnight AEST rendered in UTC — date-bucketing must shift +10h or every payment lands a day early. Found because the live smoke's 7-day window showed 0 scheduled.
LyboAI docs ≠ code: the documented connectors/<key>.ts registry doesn't exist (catalog-template executor + Fastify instead) — bridge built against the code, not the docs. Also: default bot guardrails would silently suppress tool-grounded answers (low-confidence fallback), and from-template strips aiConfig — both patched.
Live keys were exposed in a screenshot — rotation advised; build uses test keys only.

Key decisions

Do / Ask / Fix triad (huddle, ~19:50): recovery-only was too narrow — failures are rare events; daily habit requires conversational billing setup (Do) + money Q&A/digest (Ask) on top of recovery (Fix). Cost: 2 extra tools + prompts. Delivery: feed + digest first, chat second.
MCP-first, bridge for LyboAI: one Pinch core consumed by external AI hosts directly and by LyboAI through a new generic MCP bridge — a platform upgrade (any MCP now plugs into LyboAI), Pinch first.
Approval lives in the tool layer: every write tool refuses without confirm:true and returns a preview — so no host (chat, flow, UI) can move money without an explicit human step. Refund cap env-enforced.
Payment-link-first collections for the hackathon (recommended by Pinch's own managed-merchants guide); recurring schedules post-hackathon. metadata passthrough used for correlation instead of fragile description markers.
Split payments in-scope (founder call, Fri ~22:00): shared-cost collection for service businesses is an underserved wedge — whenever several businesses share one bill (a studio, a co-hosted program, an academy cost pool, a community event), whoever fronts it becomes the group's unpaid lender. Payment-splitting also sits on Pinch's own inspiration list. Composed entirely from verified primitives (links + metadata passthrough); Remi's exposure thresholds (>14 days or >25% of total) make the imbalance visible and chase it down. Use-case examples were later rewritten as fully original scenarios (see 23:45 originality pass).
Statement of accounts added; Xero + report-suite deferred to roadmap — First Submission locks the concept Sunday; Polish Week forbids new features. Email follow-up via CoachPlus's existing email adapter is the Saturday stretch item.
